# 01. NFC 프로토콜 기초

앱 만들기 전에 딱 필요한 만큼만 이론 정리. NFC는 "13.56MHz에서 10cm 이내로 통신하는 근거리 무선"인데, 그 위에 프로토콜이 층층이 쌓여 있다.

## 1. 프로토콜 스택 한눈에 보기

```
┌─────────────────────────────────────┐
│  앱 데이터 (URL, 텍스트, 커스텀)      │
├─────────────────────────────────────┤
│  NDEF (NFC Data Exchange Format)    │ ← 데이터를 담는 표준 봉투
├─────────────────────────────────────┤
│  태그 타입 (Type 1~5) / ISO-DEP     │ ← 태그 종류별 읽기/쓰기 방식
├─────────────────────────────────────┤
│  ISO 14443 A/B, FeliCa, ISO 15693   │ ← 무선 규격 (변조, 충돌방지)
├─────────────────────────────────────┤
│  13.56MHz RF (물리층)               │
└─────────────────────────────────────┘
```

## 2. NFC의 3가지 동작 모드

| 모드 | 설명 | 안드로이드 API | 예시 |
|------|------|---------------|------|
| **Reader/Writer** | 폰이 리더가 되어 태그를 읽고 씀 | `NfcAdapter` + `Tag` | 스마트 포스터, 재고 태그 |
| **Card Emulation (HCE)** | 폰이 카드인 척 함 | `HostApduService` | 삼성페이, 교통카드, 출입증 |
| **P2P** | 폰끼리 데이터 교환 | ~~Android Beam~~ (API 29에서 삭제됨) | 이제는 사실상 사용 안 함 |

> ⚠️ P2P(Android Beam)는 Android 10에서 제거됐다. 폰끼리 통신하고 싶으면 **한쪽이 HCE(카드 역할), 다른 쪽이 Reader 역할**을 하는 방식으로 구현한다. 이게 요즘 표준 패턴.

## 3. NDEF — 데이터의 봉투

NDEF 메시지는 1개 이상의 **레코드**로 구성된다.

```
NDEF Message
└── NDEF Record
    ├── TNF (Type Name Format, 3비트) — 타입의 분류 체계
    ├── Type — "T"(텍스트), "U"(URI) 등
    ├── ID (옵션)
    └── Payload — 실제 데이터
```

예: `https://example.com`을 담은 URI 레코드의 payload는
`0x04` (= "https://" 축약 코드) + `example.com` 바이트.

## 4. APDU — 스마트카드와의 대화

HCE나 ISO-DEP 태그(교통카드 등)와 통신할 때는 **APDU**(Application Protocol Data Unit)라는 명령/응답 단위를 쓴다. ISO 7816-4 규격.

**Command APDU (리더 → 카드):**

| 필드 | 크기 | 의미 |
|------|------|------|
| CLA | 1바이트 | 명령 클래스 (보통 0x00) |
| INS | 1바이트 | 명령 종류 (예: 0xA4 = SELECT) |
| P1, P2 | 각 1바이트 | 파라미터 |
| Lc | 0~3바이트 | 보내는 데이터 길이 |
| Data | Lc바이트 | 데이터 |
| Le | 0~3바이트 | 기대하는 응답 길이 |

**Response APDU (카드 → 리더):**

| 필드 | 의미 |
|------|------|
| Data | 응답 데이터 |
| SW1 SW2 | 상태 코드. `90 00` = 성공, `6A 82` = 파일 없음 |

**모든 대화의 시작 = SELECT AID:**

```
리더 → 카드: 00 A4 04 00 07 F0010203040506 00
              │  │        │  └ AID (앱 식별자, 7바이트)
              │  └ INS: SELECT
              └ CLA
카드 → 리더: 90 00  (알겠어, 그 앱 나야!)
```

HCE 앱을 만들 때 우리가 정하는 게 바로 이 **AID**다. 리더가 우리 AID를 SELECT하면 안드로이드가 우리 서비스로 APDU를 라우팅해준다.

## 5. 안드로이드에서 태그를 만나면 벌어지는 일

1. 폰이 태그 감지 → 시스템이 태그 기술 분석 (`NfcA`, `IsoDep`, `Ndef`...)
2. 인텐트 디스패치 우선순위:
   `ACTION_NDEF_DISCOVERED` > `ACTION_TECH_DISCOVERED` > `ACTION_TAG_DISCOVERED`
3. 포그라운드 앱이 **Reader Mode**(`enableReaderMode`)를 켜뒀다면 인텐트 시스템을 건너뛰고 콜백으로 직접 받음 ← **요즘 권장 방식**
