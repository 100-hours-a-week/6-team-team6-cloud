# Billage 인프라 아키텍처 문서

> 작성일: 2026-02-10
> 버전: 2.0

---

## 1. 개요

Billage 프로젝트는 **v1 (Big Bang)** 에서 **v2 (Scalable)** 아키텍처로 마이그레이션 중입니다.

| 버전 | 아키텍처 | 상태 |
|------|----------|------|
| v1-bigbang | 단일 EC2 (모놀리식) | 운영 중 |
| v2 | ASG + ALB + RDS + Redis | 구축 중 |

### 3.2 특징

| 항목 | 설명 |
|------|------|
| **구조** | 단일 EC2에 모든 서비스 (FE + BE + AI + DB) |
| **리버스 프록시** | Nginx (SSL 종료, 라우팅) |
| **DB** | Docker 컨테이너 내 MySQL |
| **장점** | 단순함, 낮은 비용, 빠른 배포 |
| **단점** | SPOF, 스케일아웃 불가, 무중단 배포 어려움 |

## 5. 네트워크 상세

### 5.1 VPC CIDR 할당

| VPC | CIDR | 용도 |
|-----|------|------|
| Dev VPC | 10.0.0.0/16 | 개발 환경 |
| Prod VPC | 10.1.0.0/16 | 운영 환경 |
| Management VPC | 10.2.0.0/16 | VPN, 모니터링 |

### 5.2 서브넷 할당 (Dev VPC 기준)

| 서브넷 | CIDR | AZ | 타입 | 용도 |
|--------|------|-----|------|------|
| public-subnet | 10.0.1.0/24 | 2a | Public | v1 EC2, v2 ALB |
| public-subnet-c | 10.0.2.0/24 | 2c | Public | v2 ALB (Multi-AZ) |
| private-subnet-a | 10.0.10.0/24 | 2a | Private | v2 RDS/Redis |
| private-subnet-c | 10.0.11.0/24 | 2c | Private | v2 RDS/Redis |

## 7. 환경별 스펙 비교

### 7.1 v2 Dev vs Prod

| 항목 | Dev | Prod |
|------|-----|------|
| **ASG 구조** | 서비스별 3개 (BE, FE, AI) | 서비스별 3개 (BE, FE, AI) |
| **ASG (각 서비스)** | min=1, max=1 | min=2, max=4 |
| **EC2** | t4g.small (2 vCPU, 2GB) | t4g.medium (2 vCPU, 4GB) |
| **RDS** | db.t4g.micro, Single-AZ | db.t4g.medium, Multi-AZ |
| **Redis** | cache.t4g.micro, 1 node | cache.t4g.small, 2 nodes |
| **ALB** | 동일 | 동일 |
| **EBS** | 20GB gp3 | 30GB gp3 |
| **Security Group** | 서비스별 분리 (BE/FE/AI) | 서비스별 분리 (BE/FE/AI) |

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    CI/CD Pipeline (v2 - 서비스별 분리)                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│   Developer                                                              │
│       │                                                                  │
│       │ git push (BE repo / FE repo / AI repo)                          │
│       ▼                                                                  │
│   ┌─────────────────────────────────────────────────────────────────┐   │
│   │                      GitHub Actions                              │   │
│   │                                                                  │   │
│   │  1. Build                                                        │   │
│   │  2. Test                                                         │   │
│   │  3. OIDC Auth  ← billage-github-actions-role                     │   │
│   │  4. ECR Push   ← billage-be / billage-fe / billage-ai            │   │
│   │  5. ASG Refresh ← 해당 서비스 ASG만 Refresh                       │   │
│   └────────────────────────────┬────────────────────────────────────┘   │
│                                │                                         │
│                                │ StartInstanceRefresh                    │
│                                ▼                                         │
│   ┌─────────────────────────────────────────────────────────────────┐   │
│   │             해당 서비스 ASG (BE or FE or AI)                     │   │
│   │                                                                  │   │
│   │   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐          │   │
│   │   │ ASG-Backend │   │ASG-Frontend │   │   ASG-AI    │          │   │
│   │   │ (BE 배포시) │   │ (FE 배포시) │   │ (AI 배포시) │          │   │
│   │   └──────┬──────┘   └──────┬──────┘   └──────┬──────┘          │   │
│   │          │                 │                 │                  │   │
│   │          └─────────────────┼─────────────────┘                  │   │
│   │                            │ Rolling Update                      │   │
│   │                            │ - 새 인스턴스 시작                   │   │
│   │                            │ - Health Check 통과                 │   │
│   │                            │ - 이전 인스턴스 종료                 │   │
│   │                            │                                     │   │
│   └────────────────────────────┼────────────────────────────────────┘   │
│                                │                                         │
│                                │ Pull from ECR                           │
│                                ▼                                         │
│   ┌─────────────────────────────────────────────────────────────────┐   │
│   │                      New Instance                                │   │
│   │                                                                  │   │
│   │   1. ECR Login (aws ecr get-login-password)                     │   │
│   │   2. Docker Pull (해당 서비스 이미지만)                          │   │
│   │   3. Docker Run (단일 컨테이너)                                  │   │
│   │   4. Health OK → ALB Target Group                               │   │
│   │                                                                  │   │
│   └─────────────────────────────────────────────────────────────────┘   │
│                                                                          │
│   장점:                                                                  │
│   - 서비스별 독립 배포 (BE 배포 시 FE/AI 영향 없음)                      │
│   - 서비스별 독립 스케일링                                               │
│   - 장애 격리 (한 서비스 장애가 다른 서비스에 영향 없음)                  │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```
